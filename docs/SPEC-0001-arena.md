# SPEC-0001-arena: два человека, два реальных LLM-агента, один наблюдаемый торг

## Problem

Торг по сделкам отнимает время. Владелец хочет делегировать торг своему агенту (Codex / Claude Code), но оставить за собой условия и контроль: видеть, что происходит, и не светить свои лимиты оппоненту.

## Solution

Комната на двоих людей. Каждый описывает сделку одним текстом в вебе и отдаёт бриф-ссылку своему агенту. Бриф — plain text по curl (`/a/:room/:side/:token`), агент торгуется по HTTP без репо и WebSocket. Оба человека смотрят общую live-ленту.

## Поток (source of truth)

1. A создаёт комнату → `ownerUrlA` (себе) + `inviteUrl` (оппоненту) + `observerUrl` (общий).
2. A пишет условия текстом → получает бриф-ссылку `/a/...` для своего агента.
3. B открывает инвайт → `claim` → пишет условия → получает бриф-ссылку для своего агента.
4. Агенты опрашивают `agent-state` и ходят через `agent-message`. Торг стартует только после обеих подач.
5. Финал: `DEAL_AGREED` (валидный ACCEPT) / `FAILED` (REJECT или лимит раундов).

## Условия сделки

Одно обязательное поле — свободный текст (1..2000 символов). Числовые `desiredPrice`/`walkAwayPrice` опциональны: их понимают детерминированный CLI и серверный gate; LLM-агенты руководствуются текстом. Направление чисел (A: desired <= walkAway, B: desired >= walkAway) и предел цены хода проверяются только когда числа заданы.

## Протокол оффера

`{ price, currency, terms, status, accepts? }`, `status = PROPOSE | ACCEPT | REJECT`.
`ACCEPT` обязан содержать `accepts` = id последнего `PROPOSE` оппонента. Ход вне `nextTurn` отвергается.

## Токены

- `ownerToken` (per side) — веб владельца: свои условия, своя agent-ссылка.
- `agentToken` (per side) — WS агента: свои условия + публичные ходы.
- `inviteToken` (per room) — обмен на `ownerToken` стороны B.
- Публичный снапшот не содержит токенов и условий (проверяется тестом).

## Швы для тестов

- `NegotiationEngine` — оркестратор с mock-раннерами (unit).
- `nextOffer` (TS) ↔ `cli/strategy.mjs` — паритет стратегий (unit).
- HTTP API + WS — полный поток с негативными кейсами (integration: поднимает `server.mjs`).

## Out of scope

Платежи, юр. подпись, >2 участников, персистентность комнат, LLM-провайдер (стратегии детерминированы; точка расширения — `nextOffer`), шифрование at-rest.
