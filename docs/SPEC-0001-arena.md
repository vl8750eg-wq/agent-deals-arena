# SPEC-0001-arena: два человека, два CLI-агента, один наблюдаемый торг

## Problem

Торг по сделкам отнимает время. Владелец хочет делегировать торг агенту, но оставить за собой условия и контроль: видеть, что происходит, и не светить свои лимиты оппоненту.

## Solution

Комната на двоих людей. Каждый вводит свои условия в вебе и отдаёт agent-ссылку своему агенту. Агенты торгуются из командной строки по очереди под контролем сервера. Оба человека смотрят общую live-ленту.

## Поток (source of truth)

1. A создаёт комнату → `ownerUrlA` (себе) + `inviteUrl` (оппоненту) + `observerUrl` (общий).
2. A вводит условия → получает `agentUrl` + CLI-команду для своего агента.
3. B открывает инвайт → `claim` → вводит условия → получает agent-ссылку для своего агента.
4. Агенты подключаются по WS с agent-токенами. Торг стартует только после обеих подач.
5. Финал: `DEAL_AGREED` (валидный ACCEPT) / `FAILED` (REJECT или лимит раундов).

## Протокол оффера

`{ price, currency, terms, status, accepts? }`, `status = PROPOSE | ACCEPT | REJECT`.
`ACCEPT` обязан содержать `accepts` = id последнего `PROPOSE` оппонента. Ход вне `nextTurn` отвергается.

## Токены

- `ownerToken` (per side) — веб владельца: свои условия, своя agent-ссылка.
- `agentToken` (per side) — WS агента: свои условия + публичные ходы.
- `inviteToken` (per room) — обмен на `ownerToken` стороны B.
- Публичный снапшот не содержит токенов и условий (проверяется тестом).

## Швы для тестов

- `NegotiationEngine` — оркестратор с mock-раннерами (unit).
- `nextOffer` (TS) ↔ `cli/strategy.mjs` — паритет стратегий (unit).
- HTTP API + WS — полный поток с негативными кейсами (integration: поднимает `server.mjs`).

## Out of scope

Платежи, юр. подпись, >2 участников, персистентность комнат, LLM-провайдер (стратегии детерминированы; точка расширения — `nextOffer`), шифрование at-rest.
